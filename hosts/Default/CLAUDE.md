# Default Host Configuration

This directory contains the host-specific configuration for the "Default" host. This is where you customize the system for your specific hardware and preferences.

## Configuration Files

- **configuration.nix** - Main host configuration with module imports and system settings
- **hardware-configuration.nix** - Auto-generated hardware-specific settings (do not edit manually)
- **host-packages.nix** - Host-specific package selections
- **variables.nix** - Central configuration variables that drive the entire system setup

## Core Configuration

### variables.nix
**Purpose**: Central configuration hub that defines user preferences and system settings

**Key Variables**:
```nix
{
  # User Information
  username = "player00";
  hostname = "nixos";

  # Desktop Environment
  desktop = "hyprland";          # Options: "hyprland", "i3-gaps", "gnome", "plasma6"

  # Application Preferences
  terminal = "kitty";             # Options: "kitty", "alacritty"
  browser = "firefox";            # Options: "firefox", "floorp", "zen"
  editor = "nvim";                # Options: "nvim", "vscode", "helix", "emacs", "nvchad"
  fileManager = "yazi";           # File manager preference

  # Appearance
  theme = "Catppuccin";           # Visual theme selection
  themeVariant = "mocha";         # Theme variant/flavor

  # Hardware
  gpu = "nvidia";                 # Options: "nvidia", "amdgpu", "intel"

  # Localization
  timezone = "America/Chicago";
  locale = "en_US.UTF-8";
  keymap = "us";

  # Features
  gaming = false;                 # Enable gaming-related packages and settings
  flatpak = false;                # Enable Flatpak support
}
```

### configuration.nix
**Purpose**: Main system configuration that imports modules and applies settings

**Structure**:
- Imports from `modules/` directory based on variables
- Applies host-specific system settings
- Configures user accounts and permissions
- Sets up networking and basic services

### hardware-configuration.nix
**Purpose**: Auto-generated hardware detection and configuration

**Important**: This file is automatically generated and should not be edited manually
- Contains boot loader configuration
- Defines kernel modules for detected hardware
- Sets up filesystem mounts
- Configures hardware-specific kernel parameters

### host-packages.nix
**Purpose**: Host-specific package additions that don't fit into modular configuration

**Use Cases**:
- Temporary or experimental packages
- Hardware-specific utilities
- One-off package installations
- Testing new packages before modularizing

## Customization Guide

### Changing Desktop Environment
1. Edit `variables.nix` and change `desktop` variable
2. Rebuild: `sudo nixos-rebuild switch --flake ".#Default"`
3. Reboot for full effect

### Switching Applications
1. Update relevant variables in `variables.nix`:
   - `terminal` for terminal emulator
   - `browser` for web browser
   - `editor` for development editor
2. Rebuild system
3. Restart affected applications

### Hardware Changes
1. Update `variables.gpu` if changing graphics drivers
2. For new hardware, regenerate hardware config:
   ```bash
   sudo nixos-generate-config
   ```
3. Review and apply changes

### Theme Customization
1. Change `variables.theme` and `variables.themeVariant`
2. Add custom themes to `modules/themes/`
3. Rebuild for visual changes to take effect

## Module Integration

### Conditional Module Loading
The system automatically imports modules based on variables:

```nix
# Example from modules/default.nix
imports = [
  # Always loaded
  ./core
  ./hardware

  # Conditionally loaded based on variables
  (lib.mkIf (vars.desktop == "hyprland") ./desktop/hyprland)
  (lib.mkIf (vars.terminal == "kitty") ./programs/terminal/kitty)
];
```

### Variables Propagation
Variables from `variables.nix` flow through the entire system:
- Desktop modules read `vars.desktop`
- Program modules read `vars.terminal`, `vars.browser`, `vars.editor`
- Theme modules read `vars.theme`, `vars.themeVariant`
- Hardware modules read `vars.gpu`

## Common Tasks

### Adding New Packages
1. For modular packages: Add to appropriate `modules/programs/` module
2. For host-specific packages: Add to `host-packages.nix`
3. For temporary testing: Add directly to `configuration.nix`

### System Maintenance
1. **Rebuild after changes**: `sudo nixos-rebuild switch --flake ".#Default"`
2. **Check configuration**: `sudo nixos-rebuild test --flake ".#Default"`
3. **Update packages**: `nix flake update`
4. **Clean old generations**: `sudo nix-collect-garbage -d`

### Troubleshooting
1. **Build failures**: Check logs and fix syntax errors
2. **Boot issues**: Use rollback option in bootloader
3. **Hardware problems**: Verify `hardware-configuration.nix` matches actual hardware
4. **Performance issues**: Review enabled modules and packages

## Advanced Configuration

### Multiple Hosts
While this configuration defines a single "Default" host, the structure supports multiple hosts:

1. Create new host directory: `hosts/NewHost/`
2. Copy and customize configuration files
3. Update `flake.nix` to include new host
4. Rebuild with: `sudo nixos-rebuild switch --flake ".#NewHost"`

### Custom Modules
Add host-specific modules by:
1. Creating local module directory
2. Adding to `configuration.nix` imports
3. Using variables for conditional loading

### Environment Variables
Set system-wide environment variables in `configuration.nix`:
```nix
environment.variables = {
  EDITOR = "nvim";
  BROWSER = "firefox";
  TERMINAL = "kitty";
};
```

## Backup and Recovery

### Configuration Backup
The entire configuration is version-controlled:
- Track changes with git
- Commit major configuration changes
- Tag stable configurations

### System Backup
- Use the built-in rollback functionality
- Create system snapshots: `sudo nixos-rebuild build --flake ".#Default"`
- Keep old generations for easy rollback

### Recovery Procedures
1. **Boot failure**: Use previous generation from bootloader
2. **Configuration error**: Revert to previous git commit
3. **Data loss**: Restore from backups (ensure you have backups!)
